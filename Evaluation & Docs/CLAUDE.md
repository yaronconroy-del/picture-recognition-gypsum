# Evaluation & Docs

Role: tracking how well the model is doing and writing down decisions — the project's memory, not its code.

What's here:
- `Project Workflow.md` — the project overview: the idea, the dataset, and the intended workflow. Moved here from the project root.
- `filter-guide.html` — static copy of the "Filter State Field Guide" Claude artifact explaining the 5 dataset classes. Images are hosted assets, so open the live link (noted in the file) to actually see it rendered.
- `project-status.html` — static, self-contained copy of the "Gypsum Recognition Progress" status page (phase-by-phase done/to-do breakdown). Open directly in a browser.
- `Final Presentation.pptx` / `.pdf` — the course submission deck (stage 8), covering the guideline's required sections: repo link, problem statement, background/motivation (incl. the monetized business case), methodology, experiments/results, and conclusions/limitations/further directions. Built with `python-pptx`; the PDF is exported 1:1 from the PPTX via PowerPoint COM automation, so the two stay in sync — regenerate both together, never hand-edit just one.
- `Final Project Report.docx` / `.pdf` — the full detailed written report (2026-09-23), 22 pages: every stage, every decision and its reasoning (a consolidated decision log), results per stage with the same tables/figures as `Project Workflow.md`, the business case, and conclusions/limitations/further directions. Built with `python-docx` (no Node.js install found on this machine, so the skill's usual docx-js approach wasn't available); the TOC is a real Word field, updated via Word COM automation on generation. The PDF is likewise exported 1:1 via Word COM — regenerate both together.
- `Final Project Report (Hebrew).docx` / `.pdf` — full Hebrew translation of the above, 21 pages, right-to-left formatted throughout: every paragraph/heading/bullet/numbered-item carries an explicit `w:bidi`, every table has `w:bidiVisual` (so column 1 renders rightmost, matching how the header list is written in the build script), every run gets an explicit complex-script (`w:cs`) font so Hebrew doesn't silently fall back to a mismatched default font, and the section itself is `w:bidi` for RTL page layout. The three pure-English reference URLs in the appendix are the one deliberate exception (`rtl=False` in the script) — LTR paragraphs so the URLs read normally. Same source figures/tables as the English version; regenerate both together if the underlying numbers change.
- **v2 — the final versions** (2026-09-24): `Final Presentation v2.pptx` / `.pdf` (36 slides), `Final Project Report v2.docx` / `.pdf` (23 pages), `Final Project Report v2 (Hebrew).docx` / `.pdf` (22 pages). Same format and structure as v1. Every result is swapped for the final full run on the day/night-corrected data (`Model & Training/models/full_pipeline/full_pipeline_results.json`, `Project Workflow.md` §18). The v2 versions add the mislabel finding: one photo was relabeled, see §17 (a new slide 13 and a new report §5.7), and the deck gains an appendix with each of the 17 configs' training curves and confusion matrix. The Hebrew v2 also fixes an RTL bug that v1 still has. In v1, "a ± b" values inside `w:rtl` runs rendered reversed ("0.708 ± 0.143" showed as "0.143 ± 0.708"). The v2 build moves those expressions into their own non-RTL runs. Builders: `build_deck_v2.py`, `build_report_v2.py`, `build_report_he_v2.py` (session scratchpad; not in the repo).
- `context/` — empty for now. Drop in accuracy results, evaluation notes, or decision logs as you go.

Also see `../final project/` (repo root) — a curated, submission-ready copy of the deck, the report, the consolidated notebook, the two demo scripts, and the EDA plots, assembled for zipping up. Not tracked in git (it's a local staging folder, not a repo artifact) — regenerate it by re-copying from here and `Model & Training/` if any of the source files change. `../final project v2/` is the equivalent staging folder for the **final** submission. It holds the v2 reports (DOCX + PDF, English + Hebrew), the v2 deck (PPTX + PDF) and `full_pipeline.ipynb`. Like v1 it is untracked, so re-copy it if the sources change.
