Project phases

1. Data collection
Photos captured and sorted by hand
 Done
  • 176 photos captured from the filter's camera (WhatsApp exports), across day and night conditions
  • Manually sorted into 5 classes: valid day/night, invalid day/night, empty filter
  • Filenames randomized (img_<id>.jpeg) with a manifest back to the originals — no ordering that leaks the label
2. Project setup
Repo, docs, and dataset tooling in place
 Done
  • Folder structure organized by area (dataset/training vs. evaluation/docs)
  • Workflow write-up documenting the idea, dataset, and every decision as it was made
  • Project pushed to a GitHub repo (now public), under version control
  • Reusable scripts + a project skill for adding new photos to the dataset consistently
3. Preprocessing
Getting the raw photos ready to train on
 Done
  • Camera's burned-in timestamp overlay masked out before training
  • Four label schemes built from the same 176 photos: lite (3-class), extended (5-class), no-empty collapsed (2-class), no-empty split (4-class)
  • Leakage-safe train/test splits by real capture session (not per-image), at three ratios each: 80/20, 75/25, 70/30, plus K-fold CV
  • The scarce "empty" class always kept ≥3 images in train, whatever the ratio
4. Model training & optimization
Transfer-learned classifier, tuned several ways
 Done
  • PyTorch + a pretrained backbone (MobileNetV2), fine-tuned rather than trained from scratch
  • Compared label schemes, split ratios, and cross-validation folds across 23 configs
  • Ran cross-validation for a more reliable accuracy estimate than one small test set
  • Tried oversampling the rare "empty" class on top of class-weighted loss (result: no real improvement)
  • Consolidated every experiment into one single-run notebook (`full_pipeline.ipynb`) that trains each config exactly once
5. Evaluation
Measuring how well the model actually works
 Done
  • Per-class precision/recall/F1 and confusion matrices on held-out test sessions
  • Cross-validation confirms it's not just a lucky single split
  • ROC/precision-recall/calibration analysis found the default 0.5 cutoff was under-flagging real faults — tuned thresholds sit closer to ~0.3–0.5
  • Tried ensembling, test-time augmentation, and probability calibration to push results further — an honest negative result, none beat the best single model
  • Finding: folding the "empty" class into "invalid" (no-empty split, 4-class) beats every other scheme on a same-ground-truth comparison — ROC AUC 0.852 vs. 0.808 for the next-best
6. Label-scheme decision
Lock in the final class scheme for the main model
 Done
  • Decided: no-empty split (4-class) — valid/invalid × day/night, "empty filter" folded into invalid rather than kept as its own class
  • Resolved by comparing every scheme against the same ground-truth definition of "invalid," rather than each scheme's own — the apples-to-apples read that broke the earlier toss-up
  • Promoted model: `gypsum_classifier_split_70_30.pt`, to be produced by `full_pipeline.ipynb`; extended (5-class) kept on as the runner-up candidate, not deleted
  • Caveat stated plainly in the docs: still a 176-photo dataset, single seed, CPU-trained runs throughout
7. Demo & deployment
Putting the model in front of a real photo
 Done
  • A local script (`predict.py`) that classifies one new photo on the spot — auto-picks the best available model, prints class + confidence + a VALID/INVALID call; spot-checked correct on 2 of 3 sample photos, with the one miss landing on the model's known-weak "empty" class
  • Sample new frames from the live camera feed — simulated via `watch_camera_feed.py`, which watches a folder and classifies each new photo within seconds; a stand-in for a real camera connection until that's decided (see below)
  • Flag "invalid" states to an operator — prints a clear `ALERT: INVALID` line; tested with a dropped-in invalid photo and it fired correctly
  • Not done: the *real* camera source (RTSP stream, etc.) and a *real* alerting channel (SMS/dashboard/log) instead of console-only — open deployment decisions, not yet made
