# Model & Training

Role: this is where the gypsum-filter classifier actually gets built — the labeled dataset and everything involved in turning it into a trained model.

What's here:
- `pictures/extended version/` — the original 5-class dataset (valid day/night, invalid day/night, empty filter), preserved as-is.
- `pictures/simple version/` — the same 176 photos regrouped into the 3 classes actually used for training (`valid`, `invalid`, `empty` — day/night collapsed). Every file here is a copy of one in `extended version/`, same filename.
- `pictures/no-empty version/` — a 4th label scheme: `empty` redefined as a kind of invalid rather than its own class. Same 176 photos as `extended version/`, but the 8 `מסנן ריק` photos were manually moved into `לא תקין יום`/`לא תקין לילה` (6 day, 2 night), so that folder no longer exists here. Read at two granularities, same pattern as lite/extended: **collapsed** (2-class: `valid`/`invalid`) and **split** (4-class: `valid_day`/`valid_night`/`invalid_day`/`invalid_night`).
- `scripts/rename_images.py` — the one-off script that gave the original 176 photos their random `img_<id>.jpeg` names and wrote the manifest. Kept for reproducibility; don't re-run it (it would re-randomize already-renamed files).
- `scripts/add_photos.py` — the ongoing version for new photos: renames new files in `extended version/`, logs them to the manifest, and mirrors each one into the matching `simple version/` folder (see the `add-dataset-photos` skill).
- `scripts/build_dataset_index.py` — builds `dataset_split.csv`, with **independent leakage-safe splits per scheme** (by real capture session, not per-image), at three ratios each (80/20, 75/25 as `_75`, 70/30 as `_70`) plus a K-fold CV assignment, for all four schemes: lite (`label`/`split*`/`fold_lite`, k=3), extended (`extended_label`/`split_extended*`/`fold_extended`, k=2), no-empty collapsed (`noempty_label`/`split_noempty*`/`fold_noempty`), no-empty split (`noempty_split_label`/`split_noempty4*`/`fold_noempty4`). CV k is auto-capped per scheme by `determine_k()` to whatever the scarcest class's session count actually supports — 4-fold was tried for the no-empty schemes but only 3-fold (collapsed) / 2-fold (split) turned out feasible: the relocated empty photos' timestamps mostly fall inside existing invalid sessions rather than creating new independent ones. The `empty` class (lite/extended only) is floored at ≥3 train images regardless of ratio. Splits are independent per scheme because a "session" in one scheme doesn't line up with sessions in another — see the note on `daynight` below.
- `dataset_split.csv` — generated output of the script above; what the notebooks/scripts read.
- `notebooks/train_and_evaluate.ipynb` — the main model: data loading, augmentation, a pretrained-backbone classifier, a small hyperparameter comparison, evaluation on the held-out test set, and export. Uses the lite (3-class) scheme, 80/20 split. Runs in Google Colab (see the notebook's own setup cell for how to clone this private repo there).
- `scripts/train_and_evaluate.py` — the same pipeline as the notebook above, as a plain script (`--quick` for a fast local CPU smoke test; drop `--quick` for a real run, though Colab's GPU is much faster).
- `notebooks/compare_label_schemes.ipynb` / `scripts/compare_label_schemes.py` — A/B test #1: lite vs. extended scheme, both 80/20, same fixed config. Saves to `models/label_scheme_comparison/` (only `comparison.json` is committed — the two `.pt` files are an experiment artifact).
- `notebooks/optimize_models.ipynb` / `scripts/optimize_models.py` — A/B test #2, broader: reuses the 80/20 baseline above and adds 75/25 + 70/30 splits, K-fold CV, and a `WeightedRandomSampler` variant, for both schemes (9 result rows total). Saves `models/optimization_sweep/optimization_results.json`. **Finding**: the extended (5-class) scheme beat lite on every split ratio and in cross-validation — most notably in CV, the most trustworthy read here (averaged over independent sessions): extended 72.3% ± 0.5 vs. lite 63.3% ± 9.5 accuracy. The oversampling variant made no difference over the existing class-weighted loss alone. See `Evaluation & Docs/Project Workflow.md` §6 for the full numbers and what this might mean for the label-scheme decision.
- `notebooks/train_extended_70_30.ipynb` / `scripts/train_extended_70_30.py` — trains the sweep's best config for real (the other two scripts above only measured it) and saves the weights: `models/gypsum_classifier_extended_70_30.pt` + `.json` (a *candidate* main model, pending the label-scheme decision — not yet promoted over `gypsum_classifier.pt`, the lite model `train_and_evaluate.*` produces). Also saves `models/extended_70_30_training_curves.png` and `..._confusion_matrix.png`. On the real 10-epoch run: 64.8% accuracy natively (5-class), 70.4% / 0.714 invalid-recall collapsed to the lite scale — close to but not identical to the sweep's number for the same config (0.741), which is expected: tiny test sets (n=54) are noisy, and exact RNG draws differ slightly between scripts even at the same seed. Same overall conclusion either way.
- `notebooks/optimize_noempty_models.ipynb` / `scripts/optimize_noempty_models.py` — the same ratio/CV sweep, run on the no-empty scheme (both granularities). Saves `models/optimization_sweep_noempty/optimization_results.json`. **Finding (the headline result of the whole optimization effort)**: no-empty split (4-class) beat every scheme tried, on CV — 77.4% ± 1.9 accuracy / 71.1% ± 5.4 invalid recall, ahead of the previous best (extended, 72.3% ± 0.5). No-empty collapsed (2-class) scored well on single splits but its CV variance is far too high to trust (±14.3 points — one fold dropped to 50.7%). See `Evaluation & Docs/Project Workflow.md` §8.
- **Keep every `.py`/`.ipynb` pair in sync** — when the modeling logic changes in one, mirror the change into the other.
- `models/` — `gypsum_classifier_extended_70_30.pt` (from `train_extended_70_30.*`, trained for real) is here now; `gypsum_classifier.pt` (the lite model `train_and_evaluate.*` would produce) hasn't been trained for real yet — only smoke-tested. See `models/README.md`.
- `context/` — empty for now. Drop in notes on your training environment, model choices, hyperparameters, etc. as you go.

**Note on `daynight`**: despite the name, the source timestamps show `day`- and `night`-labeled photos interleaved within the same few seconds of each other (see `Evaluation & Docs/Project Workflow.md` §3.4) — so whatever these folders actually encode, it isn't literal time-of-day. Worth clarifying with whoever collected the photos before leaning on it in the report.
